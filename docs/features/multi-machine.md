### T28: Spike: iroh peering
depends: T10
touches: docs only
goal: Confirm iroh fits the `Link` port and decide the pairing and discovery design.
acceptance:
- A prototype in a scratch crate (not merged): two hosts exchange wire messages over iroh across NAT through relays.
- Decide on: node identity storage, pairing (ticket via `shepherd pair` / `shepherd join <ticket>`), discovery of known
  peers on start, and trust (an allowlist of node IDs).
- Report the latency of keystroke round-trips through a relay compared with a direct connection.
out of scope: production code.
notes: (binding) One machine only: two host processes on localhost, one run relay-only (direct paths disabled) to stand in
for NAT; measure both. Use n0's default public relays (no self-hosted relay, no accounts). Prototype lives under the
scratchpad, never in the repo or the user's home; identity keys in a tempdir. Deliverable: a "Spike T28" section in
docs/architecture.md with evidence (iroh version, API used, numbers with how measured) and a recommended design, plus the
proposed `Link` adaptation; the PM records the decision.

### T29: Machine identity and names
depends: T28, T11
touches: core::host, adapters::peers, tui::sidebar
goal: Every host has a stable identity and a human name.
acceptance:
- The host generates and persists a key on first run. `machine` in envelopes is derived from it.
- The name comes from config `[machine] name`, defaulting to the hostname. A rename appends `_shepherd/machine/renamed`.
- Sidebar line 2 shows the machine name.
scope: core, adapters, tui
accepted (decision 0019): the key is `~/.shepherd/identity.key` (32 raw ed25519 bytes, 0600, `O_EXCL`), generated by the
runtime; `MachineId` is the iroh node ID's lowercase hex. See "Spike T28" in `docs/architecture.md`.
notes: (binding)
- A `MachineIdentity` port (trait in core, fake in testkit, contract run against both): `load_or_create(&self) ->
  Result<MachineKey, IdentityError>` where the real adapter reads `~/.shepherd/identity.key` or creates it (O_EXCL, 0600,
  inside the 0700 root via the shared private_fs helper; a wrong mode/size/type is an error, never overwritten). Core gets
  only the derived `MachineId` (and never the secret bytes). The adapter uses iroh's `SecretKey` (iroh 1.x,
  `default-features = false`, the features the spike used) so T30 binds with the same key; add the dependency to
  `shepherd-adapters` only.
- Existing logs already hold `machine: "local"`. Entries recorded as `"local"` are read as this machine (one alias, in core),
  so old sessions keep working after upgrade; new entries carry the node id. Test replay of a mixed log.
- The name: config `[machine] name` (display_safe, non-empty, ≤ 64 graphemes), else the hostname (libc `gethostname` in the
  adapter, display_safe), else "this machine". On start, if it differs from the last recorded name, append
  `_shepherd/machine/renamed { name }` (additive frame, documented in docs/acpp.md). The hello answer carries the machine's
  id and name to clients (additive).
- Sidebar line 2 shows the name instead of `local` (through draw.rs); snapshot. A hot swap keeps the same identity.
- Tests never touch the real `~/.shepherd`; the real host binary in tests gets a tempdir HOME.

### T30: Pairing and trusted peers
depends: T29
touches: ports::peers, core::host, adapters::peers, shepherd (cli)
goal: Connect your machines once, and they find each other on every start.
acceptance:
- `shepherd pair` prints a ticket. `shepherd join <ticket>` on another machine adds each machine to the other's
  trusted peers, as `_shepherd/peer/trusted` in each host log.
- Connections from untrusted node IDs are rejected. This is tested in the contract with the fake.
- `Peers` port with contract, fake, and iroh adapter.
scope: core, testkit, adapters, shepherd
accepted (decision 0019): ticket = `iroh_tickets` `PairTicket {addr, name, token}`. The token is 16 bytes, single use
(consumed by the first attempt), and expires after 10 min; the pair ALPN is accepted only while one is pending. Trust is
enforced in iroh's `after_handshake` hook against the set core folds from `peer/trusted`. Discovery: `presets::N0` address lookup
plus a `MemoryLookup` seeded from a last-address cache. Verify the pkarr/DNS route, which the spike couldn't exercise.
notes: (binding)
- `Peers` port (trait in core, stateful fake in testkit, per-case contract run against the fake and the iroh adapter). Its
  surface covers: bind with the machine key from T29 (`IrohMachineKey::secret()`), set the trusted set (data pushed from
  core), start/stop accepting the pair ALPN, dial a peer for pairing with a token, and events (pairing request with token
  and name, paired, connection from a trusted peer, refused untrusted). Write the trait in the PR description before coding.
- The real adapter's contract runs two endpoints on localhost with relays and address lookup disabled: no network in the
  gate. The pkarr/DNS discovery check is a manual step in `scripts/e2e-agents.sh`'s sibling `scripts/e2e-peers.sh`
  (opt-in, run by the user), not in the gate.
- The host binds its endpoint lazily: only while it has at least one trusted peer or a pending pairing. A host that never
  paired never goes online (so existing real-host tests and users who don't pair make no network calls).
- The 16-byte token comes from the runtime (OS randomness), reaches core as an event field, and is compared in constant
  time in the adapter; expiry is driven by Tick in core. A wrong token consumes the pending pairing.
- CLI: `shepherd pair` (asks the local host for a ticket, prints it, waits until joined or expired), `shepherd join
  <ticket>`, `shepherd peers` (list names and ids) and `shepherd unpair <name|id>` (appends `_shepherd/peer/removed`;
  the adapter drops the peer's connections at once). Frames are additive and documented in docs/acpp.md.
- Peer names and ids shown anywhere go through display_safe. The last-address cache is `~/.shepherd/peer-addrs.json`
  (0600, private_fs), non-authoritative.
- Tests never touch the real `~/.shepherd`; no test reaches n0's relays.

### T31: Remote link and merged sidebar
depends: T30, T12
touches: adapters::link (iroh), core::client, shepherd::client
goal: The client drives every trusted machine's host as if it were local.
acceptance:
- The iroh `Link` adapter passes the T10 contract.
- The client connects to the local host and to every reachable trusted peer. The session list is merged and
  sorted newest first. Each session is routed to its own host for input, resize, rename, and close.
- An unreachable peer shows as a dimmed machine group with its last-known sessions. Reconnects resume
  subscriptions from the last seen `seq` with no gaps or duplicates.
- Scenario with two fake hosts over the fake link.
- Catch-up stall detection (T11) counts "queue shrank", so a single huge line over a slow link (over 30 s to deliver) looks stalled.
  Add a drained-bytes counter to `Link` and use it for progress.
- From the T30 review: `peering.rs` `gone`'s `pending.start.is_some()` condition is untested (start, wait, the waiter's
  client goes → no StopPairing); fix its comment for the two-client race (a waiter leaving can stop a pairing whose
  start was answered but whose wait isn't sent yet).
scope: adapters, core, shepherd
accepted (decision 0019): the host owns the only iroh endpoint. The client reaches a remote host through a
`_shepherd/tunnel { machine }` conn to its local host, which splices lines to the peer with read pausing for flow control. So
"the iroh `Link` adapter" lives in the host, and the client keeps its unix link. `Link` gains `peer(conn)` and possibly
`DisconnectReason::Refused`. Also test catch-up of a multi-MB history over a relay. Measured: relayed keystroke echo is about 26–30 ms
median, direct is about 0.2–0.5 ms.

### T31a: Tunnel to a peer's host over iroh
depends: T30, F47
touches: ports::link, adapters::link (iroh), adapters::peers, shepherd::host::runtime, wire
goal: A client on this machine can open a conn to a trusted peer's host through its own local host.
acceptance:
- A client conn whose first request is `_shepherd/tunnel { machine }` (local conns only, per `Link::peer(conn) == None`)
  is spliced by the local host to an iroh conn to that trusted peer: lines pass both ways verbatim; the remote host sees an
  ordinary client conn from a trusted node and runs the normal hello. Untrusted, unknown or unreachable machine → a clear
  error answer, conn closed.
- The iroh conn side implements `Link` and passes the T10 contract (run against the fake and the iroh adapter on localhost
  with relays off). `Link` gains `peer(conn) -> Option<MachineId>` and `DisconnectReason::Refused` (additive; contract
  cases for both).
- Flow control: the local host stops reading the iroh stream while the client conn's `queued_bytes` is over a high-water
  mark (and vice versa), so a slow client back-pressures the remote host; test with a paced client and a large history.
- Stall detection progress counts drained bytes: `Link` gains a drained-bytes counter, and catch-up stall detection (T11)
  uses it, so one huge line over a slow link isn't "stalled" while it's moving. Test it with the fake.
- Reconnect to a peer with backoff when the iroh conn drops (T30 left retry to here); a tunnel whose peer drops is closed
  with `PeerGone` so the client can reconnect.
- From the T30 review: `peering.rs` `gone`'s `pending.start.is_some()` condition is untested (start, wait, the waiter's
  client goes → no StopPairing); fix its comment for the two-client race.
scope: crates/core, crates/testkit, crates/adapters, crates/shepherd
notes: (binding) Decision 0019. tokio stays in adapters; the runtime stays single-threaded. No network in gated tests
(localhost endpoints, relays and discovery off). Multi-MB catch-up over a real relay is a manual step in
`scripts/e2e-peers.sh`, not the gate.

### F52: Peer conn hardening after the tunnel
depends: T31a
touches: core::peering, shepherd::host (swap, runtime), adapters::peers
goal: From T31a's builder: gaps it left out of scope.
acceptance:
- `pair/*`, `peer/remove` and the upgrade request from a peer machine's conn (`Link::peer(conn)` not `Ok(None)`) are
  refused like tunnels are: only local clients manage pairing, trust and upgrades. Test each.
- A swap unbinds the iroh endpoint before exec, so peers see the conn close at once instead of at idle timeout; the new host
  rebinds with the same identity. Test with the fake peers port; note the real behaviour in `scripts/e2e-peers.sh`.
- Opening more tunnels to one peer than the connection's stream limit (100 concurrent streams) gives a clear error answer,
  not a hang; or the limit is raised with a stated bound.
- Lines already handed to the loop before a pause are held by the tunnel unbounded in principle (decision 0021): count them
  and close the tunnel with a clear reason past a stated cap, test with the fake.
- From T31b's review: `Client::alerts` (core client.rs ~1786) no longer checks a session's home host; with a shadowed
  duplicate id a peer's session could ring with the local bell. Restore the `homes.get(&s.id) == Some(at)` filter with a test.
scope: crates/core, crates/testkit, crates/adapters, crates/shepherd
